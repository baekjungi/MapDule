# MapDule (맵듈)

월간 일정표에서 날짜별 일정과 이동 경로를 확인하는 모바일 우선 일정 관리 UI 프로토타입입니다.

## 현재 구현 범위

- 월간·주간·일간·일정 목록 보기와 날짜별 일정 표시
- 사이드바 미니 달력 및 캘린더별 일정 표시 필터
- 모바일 화면의 선택 날짜 일정 카드 및 빠른 일정 추가 버튼
- 달력 빈 날짜에서 일정 생성, 일정 배지에서 수정·삭제
- 종일 일정, 시간, 캘린더, 장소, 메모를 관리하는 공통 일정 모달
- 모바일 햄버거 사이드바와 바텀 시트 일정 모달
- 날짜를 선택해 상세 타임라인과 이동 경로를 확인하는 화면
- 상단의 AI 일정 등록 진입 버튼
- 지각 위험 알림 카드
- 이동 시간 블록과 자투리 시간 퀘스트
- AI 자연어 일정 등록 미리보기
- 약속 지점 추천 화면
- 프로필 설정 저장
- 수동 일정 등록, 수정, 삭제 및 시간 중복 방지
- `.ics` 캘린더 내보내기와 JSON 백업·복원·초기화
- 모바일·데스크톱 반응형 레이아웃
- 가족 그룹: 초대 코드·링크, 공유 일정 및 참석자 선택
- 출발 알리기부터 도착까지의 위치 공유와 가족 지도
- 가족방 채팅: 텍스트·줄바꿈, 간단한 Google Noto Color Emoji 선택, 참여자 간 메시지 공유
- 일정별 이동방, 읽지 않은 대화방 표시와 방별 메시지 초안
- 가족 일정의 주간 반복, 출발 확인과 집으로 귀가 공유

가족을 만들거나 초대 코드로 참여하면 가족 화면의 **가족 채팅**을 사용할 수 있습니다. 새 입력창은 최대 500자이며, 가족방은 최근 1,000개, 이동방은 최근 300개를 저장합니다. 처음 열 때 최근 200개를 불러오고, 화면을 보고 있을 때 3초마다 새 대화를 확인합니다. 기존 가족 메시지와 이전 API(최대 1,000자)는 계속 호환됩니다. 엔터로 전송하고 시프트+엔터로 줄을 바꿀 수 있습니다. 한글 조합 중 엔터는 전송하지 않습니다. 메시지 전송은 구성원당 분당 20회로 제한됩니다. 전송 실패 시 입력 내용이 유지되며 오류가 표시됩니다. Google Fonts에서 Noto Color Emoji를 불러오며, 연결할 수 없으면 기기의 기본 이모지로 표시합니다. 채팅도 기존 가족 저장소를 사용하므로 별도 서비스나 API 키는 필요하지 않습니다.

입력창에는 현재 글자 수가 표시되며, 공백만 있거나 전송 중일 때는 보내기 버튼이 비활성화됩니다. 이모지 선택창은 이스케이프 키로 닫을 수 있습니다. 입력 길이는 브라우저 `maxlength`와 동일한 UTF-16 코드 단위로 계산하므로 일부 이모지는 두 자 이상으로 표시됩니다.

채팅 화면과 스타일은 기존 `family.js`·`family.css`에 통합되어 별도 채팅 스크립트나 스타일시트를 추가로 불러오지 않습니다. 날짜·시간은 한국어 월·일과 오전·오후로 표시합니다.

가족 일정의 참여자가 출발하면 이동방이 생깁니다. 일정 참여자와 작성자가 대화할 수 있으며, 이동을 공유 중이면 만료 시각이 지나도 유지됩니다. 모두 도착하면 30분 뒤 만료되고, 귀가를 설정한 일정은 이동한 모든 구성원이 집에 도착할 때까지 기다립니다. 일정 삭제 시 연결된 이동방과 위치 경로도 삭제됩니다. 시간 만료에 따른 실제 저장소 삭제는 다음 가족 상태·대화방 조회 때 실행됩니다. 귀가 대기 중 아무도 이동하지 않으면 일정 종료 2시간 뒤 만료될 수 있습니다.

출발 확인은 일정 시작 10·20·30·45·60·90분 전 또는 사용 안 함을 선택합니다. 확인 시각 5분 뒤에도 출발 기록이 없으면 가족방에 안내가 남습니다. 확인 시각 뒤에 새로 만든 일정에는 소급 알림을 보내지 않습니다. 가족의 소리·진동·5분 뒤 다시 알림은 **브라우저가 실행 중일 때만** 작동하며, 백그라운드 절전에서는 늦어질 수 있습니다. 소리는 화면을 한 번 누른 후, 시스템 알림은 별도 허용 후 사용할 수 있습니다. 별도로 저장된 일정 계산의 출발 알림에는 서버 Web Push 예약을 추가했습니다. 가족 출발 확인 전체를 푸시로 보내는 기능은 아닙니다.

귀가는 프로필의 집 주소를 지도에서 찾고, 위치 공유 동의를 받은 뒤 시작합니다. 집 좌표가 없으면 직접 도착을 누를 수 있습니다. GPS 오차가 큰 위치는 경로 표시용으로만 사용하며, 자동 도착은 오차 100m 이내의 위치로만 판정합니다.

반복 일정은 요일과 선택적 종료일을 설정하며, 한국 시간 기준 앞으로 8주까지 미리 생성하고 가족 상태 조회 때 연장합니다. 한 날짜만 수정·삭제하거나 해당 날짜부터 이후 일정을 함께 변경할 수 있습니다. 가족별 반복 규칙은 최대 50개, 생성된 일정은 최대 1,500개입니다. 한도에 걸려도 기존 일정은 유지되며 정리 안내를 표시합니다.

프로필과 개인 일정은 브라우저 로컬 저장소에 저장됩니다. 가족 일정과 이동 상태는 로컬에서 `.mapdule-data/` 파일, Azure 배포에서는 Table Storage에 저장합니다. Azure에 `MAPDULE_STORAGE_CONNECTION_STRING`을 등록해야 가족 공유 기능이 활성화됩니다. 자세한 내용은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.

JSON 백업 복원은 모든 일정의 실제 날짜, 시간 범위, 제목, 좌표와 중복 ID를 먼저 검사합니다. 잘못된 일정이 하나라도 있으면 일부만 복원하지 않고 기존 데이터를 유지합니다. AI 문장을 수정하면 이전 분석 결과는 등록할 수 없으며 다시 분석해야 합니다.

AI 일정 분석은 서버에서 Azure OpenAI를 호출하며 브라우저에는 API 키를 전달하지 않습니다. 자동차는 `KAKAO_REST_API_KEY`, 도보·대중교통은 `ODSAY_API_KEY`를 설정하면 실제 경로를 조회합니다. 미설정·장애·미지원 구간은 직선거리 추정으로 대체하며 화면에 출처와 조회 시각을 표시합니다. 대중교통은 도보 구간을 포함하지만 실시간 지연·첫차·막차를 보장하지 않습니다. 도시간 대중교통은 터미널 접근 경로를 포함하지 못하므로 추정으로 표시합니다.

## 약속 지점과 출발 알림

**약속 지점**에서 참가자 2~6명의 출발지를 선택하고 후보 1~5곳을 비교할 수 있습니다. 카카오 장소 검색 키가 있으면 가운데 좌표 반경 5km의 카페·식당·지하철역 후보를 찾습니다. 검색 결과를 직접 선택하거나 위도·경도를 입력할 수 있습니다. 순위는 이동 시간 차이, 최대 시간, 환승·도보 부담 순입니다. 이는 비교한 후보 중 순위이며 전체 지역의 최적 지점을 보장하지 않습니다. **이 장소로 일정 만들기**를 누르면 날짜·시간·가족 참석자를 확인할 수 있는 기존 일정 모달이 열리고, 등록을 눌러야 저장됩니다.

지도 화면에서 오늘의 저장된 일정을 계산한 뒤 **출발 시각에 알려 주세요**를 누릅니다. 서버 푸시 설정과 브라우저 권한이 있으면 탭을 닫아도 알림을 받을 수 있습니다. 설정이 없거나 미지원 브라우저에서는 기존 탭 알림으로 동작하며 화면에 방식이 표시됩니다. 상단 알림 센터에서도 **이 기기의 출발 알림 끄기**로 취소할 수 있습니다. 해당 일정이나 직전 일정의 시간·장소가 변경되면 브라우저가 변경을 확인할 때 이전 푸시 예약 전체를 취소하며, 새 예약에는 다시 계산이 필요합니다. 다른 기기에서 수정한 가족 일정은 이 기기가 동기화하기 전까지 기존 예약이 남을 수 있습니다.

**가족 알림(앱을 닫아도)**: 가족 화면의 **앱을 닫아도 알림 받기**를 켜면 이 기기의 푸시 구독이 가족 구성원과 연결됩니다. 1분마다 실행되는 예약 호출(`/api/push/dispatch`)이 오늘 가족 일정을 확인해 출발 확인 시각에 참여자에게 '출발할 시간이에요', 5분 뒤에도 출발 기록이 없으면 다른 가족에게 '아직 출발하지 않았어요'(가족방 안내 포함), 일정 끝 시각에 도착한 참여자가 있으면 다른 가족에게 '일정을 마쳤어요'와 귀가 설정 시 참여자에게 '집에 갈 시간이에요'를 보냅니다. 출발·도착·집 출발·집 도착은 기록되는 즉시 다른 가족에게 알립니다. 같은 알림은 한 번만 보내고(가족별 `pushlog`), 만료된 구독은 지웁니다. 가족에서 나가면 구독도 삭제됩니다.

푸시는 VAPID 키, 영속 저장소, 서버 예약 실행이 필요합니다. 로컬 서버는 실행 중 30초마다 발송을 확인합니다. 배포된 Static Web Apps에는 별도 예약 실행 서비스가 필요하며 이번 작업에서 생성·배포하지 않았습니다. HTTPS(또는 localhost)가 필요하고, iOS/iPadOS 16.4 이상에서는 홈 화면에 추가한 웹앱에서 권한을 허용해야 합니다. 기기 절전·네트워크·예약 실행 장애로 지연되거나 누락될 수 있어 중요한 약속에는 다른 알람도 사용하세요. 설정 방법과 전송 제한은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고합니다.

AI 일정 분석과 저장된 일정 계산은 Microsoft 계정 없이 사용할 수 있습니다. 남용 방지를 위해 IP별 요청 수와 서버 동시 실행 수를 제한하며, 한도 초과 시 잠시 기다린 뒤 다시 사용할 수 있습니다.

카카오 지도를 연결하려면 `index.html`의 `kakao-javascript-key` 메타 태그에 Kakao Developers의 JavaScript 키를 입력하고, Kakao Developers의 Web 플랫폼에 로컬 및 배포 도메인을 허용 목록으로 등록합니다. 키는 브라우저에 공개되므로 JavaScript 키만 사용하고 도메인 제한을 설정하세요.

## 실행

요구사항: Node.js 18 이상

로컬에서 Azure OpenAI 분석을 사용하려면 `.env.example`을 복사해 `.env`를 만들고 발급받은 값으로 채웁니다.

```env
AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com
AZURE_OPENAI_API_KEY=your-api-key
AZURE_OPENAI_DEPLOYMENT=your-deployment-name
```

실제 `.env`는 Git에서 제외됩니다. 키를 커밋하거나 브라우저 코드에 넣지 마세요. 설정 후 서버를 재시작합니다. 배포 사이트 설정은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고하세요.

```bash
npm install --prefix api
npm run check
npm start
```

브라우저에서 `http://localhost:4173`을 엽니다. 포트는 `PORT` 환경 변수로 바꿀 수 있습니다.
AI 등록 화면에 문장을 입력하고 **AI로 일정 분석**을 누른 뒤, 분석된 일정과 시간을 확인하고 등록합니다.

```powershell
$env:PORT=8080
npm start
```

## 배포

이 프로젝트는 정적 웹앱이며, 배포 시 공개할 HTML·CSS·JavaScript만 `dist/`에 모읍니다.

- Azure Static Web Apps Free에 배포되어 있습니다.
- `main` 브랜치에 푸시하면 GitHub Actions 검사 후 자동 배포됩니다.
- Azure 연결 정보, 무료 한도, 장애 확인 방법은 [DEPLOYMENT.md](DEPLOYMENT.md)를 참고합니다.

실제 서비스로 전환하기 전에 다음 작업이 필요합니다.

1. 인증과 사용자별 개인 일정 동기화 저장소 연결
2. 경로·장소 API 키 발급과 실제 경로의 운영 검증
3. 푸시 키·영속 저장소·외부 예약 실행 설정 및 실제 기기 수신 검증
4. 도시간 대중교통, 기준 출발 시각·실시간 지연 반영 확장
5. API별 비용 경보와 다중 서버에서의 전역 호출 제한

제품 요구사항은 [prd.md](prd.md), 개발 지침은 [agent.md](agent.md)를 참고합니다.
